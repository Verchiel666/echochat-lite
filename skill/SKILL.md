# 共情回应：三段推理 + 门控 + 步骤级信用

来源：EchoChat（NeurIPS 2026, arXiv:2610.04826）。论文用 RL 训练模型；这里用的是它**推理期**的部分，
不需要训练、不需要 GPU：结构化轨迹 + 门控评分 + 根因定位。

工具：`npx echochat-lite`（或在仓库里 `node echochat.mjs`）（`npx --package=echochat-lite -- node dev/eq-test.mjs` 可自检 25 项方程）。

## 什么时候用

- 回应对象有**潜台词**：文字中性但语气不对（模态冲突）、逞强、自嘲、阴阳怪气、情绪在句内变化
- 已经写了一版回应，要判断是"真的共情"还是"温暖但空洞"（共情模仿）
- 要在一组候选回应里挑一个，并说明为什么另一个不好

## 流程

1. **先固化感知证据**（不要跳过，这一步决定后面全部）
   - 有语音：转写 + 显式写韵律线索（语速、音量、句尾走向、停顿、气声）
   - 只有文字：写清"哪些是字面、哪些是推断"，别把推断写成事实
2. **写四段轨迹**，每段一句，不要合并：
   - 感知 = 情绪 + 强度 + 韵律线索（"文字中性，但发紧+快+尾音上扬 = 压抑，中高强度"）
   - 心智状态 = 潜台词 + 未说出口的需要 + 是否是试探
   - 策略 = 做什么 + **明确不做什么**（不说教、不抢先给方案）
   - 回应 = 最终文本
3. **生成 2–4 个候选**（至少一个"温暖但无依据"的反例，用来验证门控真的在起作用）
4. **打分**（LLM-as-judge，0–5；format 0/1）
   | 维度 | 5 分 |
   |---|---|
   | 感知 | 抓住隐含情绪+强度+韵律，且区分了字面与推断 |
   | 心智状态 | 潜台词与真实需要说对，不被字面拒绝骗过 |
   | 策略 | 支持方式匹配需要，且留出对方的空间 |
   | content | 回应建立在上面三段之上，具体、不空洞 |
   | audio | 语气与用户状态匹配（文本场景用文字语气判） |
5. **跑工具**：`node echochat.mjs case.json --tau 0.6`
6. **按"最弱环节"返工**，然后重跑

## 三条硬规则（论文机制 + 本机实测踩出来的）

1. **感知不过门控，改下游=自欺**。τ=0.6 时感知 <3 分，Eq.4 把推理与策略项**清零**，
   再漂亮的回应也拿不到分。案例实测："温暖空"候选 R_resp=0.860（最高），R_total 只有 0.524，垫底。
2. **不要用 SDCA 的 A_k 取最小值找根因**。门控会把上游失守时的下游分值清零，A_2/A_3 一起变负，
   argmin 会错误指到"心智状态推理"。根因看**未加门**的原始分（工具里已处理）。
3. **别用总奖励做单点决策**。同一组里"依据不对但话很暖"的轨迹总分可能只差 0.2；差的是信用方向
   （实测：错误感知拿到正优势的概率 12.47% → 门控后 2.10%）。

## 局限

- judge 由本会话模型充当（本机无 DeepSeek key，`api.deepseek.com` 401）。要换真 judge，
  在 `scores` 里填模型输出的 JSON 即可，工具只吃分数。
- 论文的训练收益复现不了（没 GPU）：EchoEval 上感知 8.23 / 推理 8.43 / 回应 9.26 是论文数字。
- τ、α、ω 都是超参；τ 越高越保守（更容易判"感知不合格"），默认 0.6 来自论文。
